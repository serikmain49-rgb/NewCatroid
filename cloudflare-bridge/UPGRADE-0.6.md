# Bridge 0.6.0

Обновлять оба JS-модуля: newcatroid-worker.js и sync-store.js. В GitHub/Wrangler это происходит одним деплоем. Сохраняются имя Worker purple-resonance-01d7, binding DB, все секреты, данные и прежние REST/MCP-маршруты.

Новый POST /api/device/sync принимает content-addressed full/delta для четырёх файлов. Старый /api/device/state работает для прежних плагинов. Файлы для чтения по-прежнему полные. Успешная delta включает project_id, request_id, проверенный SHA-256 и статистику экономии. База не совпала — FULL_EXPORT_REQUIRED, без подмены хеша.

Проверка личности: современные патчи/запросы привязаны к project_id, а не только названию. Сервер request_state ожидает текущий проект; для намеренной смены пользователь вручную отправляет состояние другой игры. Legacy-патчи без ID сохраняют старые проверки и не различают идентичные копии.

В архиве termux нужно заменить server.py и добавить рядом sync_store.py. Каталог данных/ключей оставить прежним. После обновления .nplug до 0.6 первая отправка полная; затем работает частичная. Если на телефоне остался 0.5, его полный экспорт тоже принимается.

Проверено локально: 51 Worker-проверка через SQLite D1-адаптер; 20 тестов Python, включая перезапуск, частичную сборку и другой проект. Межъязыковой тест использует данные реального Java-экспортёра. Android и живой D1 требуют отдельной проверки. Лимит полного/собранного экспорта 8 МиБ.
